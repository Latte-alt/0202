# 00. Подготовка: 4 минуты

## 1. Проверить топологию в Proxmox

В учебном задании есть: `ISP`, `HQ-RTR`, `BR-RTR`, `BR-FW`, `HQ-SRV`, `HQ-CLI`, `BR-SRV`. Коммутатор `HQ-SW` может быть реализован как VLAN-aware Linux bridge Proxmox.

| Логическое соединение | Какие ВМ | Пример назначения |
|---|---|---|
| WAN | ISP ↔ сеть экзамена | DHCP, не изолированный мост |
| ISP-HQ | ISP ↔ HQ-RTR `te0` | отдельный bridge |
| ISP-BR | ISP ↔ BR-RTR `te0` | отдельный bridge |
| HQ-LAN | HQ-RTR `te1` ↔ HQ-SRV ↔ HQ-CLI | **VLAN-aware** bridge |
| FW-NET | BR-RTR `te1` ↔ BR-FW | отдельный bridge |
| BR-NET | BR-FW ↔ BR-SRV | отдельный bridge |

**В HQ-LAN:** виртуальная NIC HQ-SRV с **Tag=100**, HQ-CLI с **Tag=200**. NIC HQ-RTR без access-тега, она получает кадры 802.1Q. Если Proxmox не умеет VLAN в выбранном bridge, сначала исправь его настройку. Убедись, что в физической сети колледжа не возникло петли.

## 2. За 15 секунд узнать, где какие интерфейсы

На ALT Linux, от `root`:

```bash
ip -br link
ip -br -4 addr
ip route
ls -l /sys/class/net
```

**Примеры имён:** ISP `ens18` (WAN), `ens19` (HQ), `ens20` (BR); BR-FW `ens18` (к BR-RTR), `ens19` (к BR-SRV); остальные — `ens18`. Порядок **не гарантирован**: сравни MAC-адреса с Proxmox `Оборудование → Сетевое устройство`.

На EcoRouter:

```text
show port brief
```

В инструкциях принято `te0` → ISP, `te1` → локальная сеть. Если у тебя другие порты, замени `te0`/`te1` в командах.

## 3. Рабочие правила на скорость

1. Вводи **весь блок для одного устройства** и перезапускай сеть один раз.
2. Команды Linux в руководстве рассчитаны на `root` (`su -`), EcoRouter — на `enable` и `configure terminal`.
3. Не перезапускай уже работающую сеть HQ-CLI ради повторного запуска старого скрипта; для `ens18` используй **один менеджер** — etcnet.
4. Делай минимум две проверки на каждом устройстве: `ip -br a`/`show ip interface brief`, затем `ping` ближайшего шлюза.
5. Настройки DNS **окончательно переключай после запуска HQ-SRV**. До этого для установки пакетов может использоваться доступный внешний DNS.
6. Скриншоты/выводы для отчёта делай сразу после успешно настроенного компонента.

## 4. Как задавать IP на ALT Linux (etcnet)

При `NM_CONTROLLED=no` сетевые конфиги хранятся в `/etc/net/ifaces/ИМЯ_ИНТЕРФЕЙСА/`. Например:

```text
/etc/net/ifaces/ens18/options
/etc/net/ifaces/ens18/ipv4address
/etc/net/ifaces/ens18/ipv4route
/etc/net/ifaces/ens18/resolv.conf
```

- `BOOTPROTO=static` — адрес вручную, `BOOTPROTO=dhcp` — получать автоматически.
- `NM_CONTROLLED=no` — интерфейс не настраивается через NetworkManager.
- `DISABLED=no`, `ONBOOT=yes` — включить и поднимать при загрузке.
- В `ipv4address` пишем `192.168.0.2/27`.
- В `ipv4route` пишем `default via 192.168.0.1`.

В руководстве конфиги создаются командами `cat > файл <<'EOF' ... EOF`: так гораздо быстрее, чем открывать редактор. Если настройка уже существует, перед перезаписью сохрани её, особенно на экзаменационном стенде:

```bash
cp -a /etc/net/ifaces /root/ifaces.backup
```

**Не запускай одновременно `nmcli con mod` и ручной etcnet для одного интерфейса.** Если NetworkManager продолжает управлять интерфейсом, переключи его на etcnet и убедись, что `NM_CONTROLLED=no` действительно действует. Делай сетевые перезапуски только через консоль Proxmox — не по SSH.

## 5. Быстрая памятка маршрутизации

- На сервере — **один маршрут по умолчанию** через ближайший маршрутизатор.
- На BR-FW — маршрут по умолчанию `192.168.3.1`, включено `ip_forward=1`.
- На HQ-RTR — маршрут по умолчанию `172.16.1.1`.
- На BR-RTR — маршрут по умолчанию `172.16.2.1`.
- У ISP WAN-шлюз приходит с DHCP; дополнительные WAN-адреса не получают default route.
- Межофисные маршруты приходят через OSPF; статические маршруты между HQ/BR обычно не нужны.
